# sagebrush-agent

Chat with Claude in [Sagebrush](https://sagebrush.space), with Claude running on your own computer.

```
npx -y <the tarball's URL>
```

It prints a link. Open it in Chrome or Firefox, and allow the folders Claude may use. Then chat.

## What it does

- It starts Claude through Anthropic's [Claude Agent SDK](https://www.npmjs.com/package/@anthropic-ai/claude-agent-sdk), with **your own Claude login**. It uses the same login as Claude Code: if you have used Claude Code on this computer, you are logged in. Otherwise run `claude` once and log in.
- It listens **only on 127.0.0.1** (the loopback address). It accepts a connection only:
  - from the Sagebrush page's origin;
  - with the one-time code it prints, valid once, for 5 minutes;
  - and only one page at a time. Before the hello, a connection may send at most 16 KiB in total and must say hello within 10 seconds; at most 4 wait at once.
- **One grant, whichever page holds it:** everything Claude does belongs to the access a page granted. Nothing started under one grant runs under another.
  - **A page that goes away** (a reload, a navigation, a lost connection): Claude's turn goes on, and so do its open questions. A workspace call waits up to 2 minutes for a page that holds the same grant, then is refused as "the page is closed". A call already sent to the page that went away is refused then and is never sent again. Messages queued in that conversation wait, and start only once a page with that grant is back.
  - **A page that comes back with the same grant** (the same grant record, no wider: its folders within the turn's, and writing or running code not newly allowed, and this computer's files neither newly allowed nor taken away) carries the turn on, answers its open questions, and gets everything it missed from the conversation's log.
  - **Runs and notebook edits after a page change:** a turn that comes back on a page runs code or edits a notebook there only if that page can tie the run or the edit to the turn (a page says what it offers when it pairs, before its grant). Otherwise the call is refused ("the page can't tie this run to its turn", or "…this edit…") and nothing is sent. A turn that stays on its first page runs and edits as before.
  - **Another grant, a wider one, a revoke, the grant's expiry, or the turn's 24 hour limit** ends the turn and refuses its queued messages, as Stop does. A reconnect never extends the expiry or the limit.
  - **A grant without an id** (from an older page), **or a Codex turn:** as before, the turn stops when its page goes away or the grant changes, its queued messages are dropped (the page is told), and its open questions count as "no".
- **Steering a running turn:** on a page that supports Steer, choosing it sends your message into the running Claude turn with priority next. The agent reports steering when submitted, delivered when Claude names it as taken, or queued if it must run as a separate turn (including Codex or a turn that ended first). An untaken steer is queued under its original scope, subject to the same grant and queue rules.
- **Notebooks:** Claude can write a Sagebrush notebook (`workspace_write_notebook`: Python, Sage, MATLAB or Magma, code and Markdown cells). It opens beside the chat; **you** run its cells, unless you allowed Claude to run code (below). When Claude reads a notebook back, it sees every cell's source whole, but the outputs are shortened: at most 8 KiB of text per output, pictures and metadata named by size, and 256 KiB of outputs in all, after which it is told which cells' outputs it doesn't see. The file itself is unchanged.
- **Files:** Claude's only file tools are the Sagebrush workspace's (`workspace_list`, `workspace_read`, `workspace_write`, …). Each call goes to the page, which checks it against the folders and permissions you granted, and does it in the workspace in your browser.
  - Claude gets no shell, no files of this computer and no settings: the SDK runs with no setting sources, in an empty temporary folder. (Through `sagebrush remote`, the person can turn on shell and files on that computer: see below.)
- **Branches and runs**, on pages that offer them: Claude can make its own branch of your workspace (`workspace_git_branch`), commit it and ask you to review it (`workspace_git_commit`), see where it stands or wait for your decision (`workspace_git_status`, `workspace_git_wait`). While "May run code" is on for the page (you choose it when you grant access, and can turn it off at any time), it can also run a notebook or a .py/.sage file (`workspace_run_notebook`, `workspace_run_file`), build a .tex (`workspace_latex_build`) and stop its run (`workspace_run_stop`).
  - The code runs in Sagebrush's sandbox in your browser, never on this computer.
  - These calls don't ask you each time: the page allows only what your grant allows. A branch is only Claude's own, and only you accept its changes, on the review page.
  - If the turn is stopped or a run's time runs out, sagebrush-agent asks the page once to stop that run.
- **Reading the web:**
  - **No question asked:** files and folder listings of public GitHub repositories (`repo_read`, `repo_list`), and Sagebrush's own docs and formats (`sagebrush_docs`). These go only to GitHub's and sagebrush.space's fixed addresses, with a strict form, a size limit, and a limit per turn.
  - **Other web pages** (`web_fetch`, this agent's own; Claude Code's WebFetch isn't used): A request to a site without a current turn grant asks you. You can allow that one request, or that site for the rest of the turn. A redirect to another site needs approval there too.
  - **A web search** (`WebSearch`) asks the same way.
  - The question shows the site and the path, never the query, and never a search's terms.
  - What a page or search returns is marked as untrusted content.
- **What asks you first, in the chat:** Web requests and searches ask as described above. Each move, rename or removal of a workspace file also asks; its question shows the path and all of that call's arguments, and your answer covers exactly those. Claude never decides on its own: the SDK runs in its manual permission mode (no auto mode, no bypass), only our MCP server is loaded, and any other tool is refused.
- **What leaves your computer:** the conversation goes to Anthropic, through the SDK, as with any Claude session. A web search you allow goes to Anthropic's search. A page you allow, and the GitHub and Sagebrush docs reads, go from this computer, only over https, only to public addresses, and never through a proxy.
- **What is kept on disk:** like Claude Code, the SDK saves each conversation's transcript (your messages, Claude's replies, and the tools' results, including file contents Claude read) under `~/.claude/projects/`, in a folder named after the daemon's empty working folder. That is how a conversation goes on from one message to the next. When you stop sagebrush-agent with Ctrl+C, it waits (up to 10 seconds) for running turns to stop, then deletes this run's transcripts and the working folder, and says so; if it can't delete something, it says what and where it is. If it is killed or crashes, they stay there until you delete them. The SDK may also keep its usual logs under `~/.claude/`.

Options: `--port N` (default: a free port) and `--origin ORIGIN` (another allowed page origin, exact: like `https://example.org`, no path or wildcard). The environment variable `SAGEBRUSH_AGENT_PAGE` changes only the printed link, never which pages may connect.

Press Ctrl+C to stop.

## Delegate: a task Claude works on with the page closed

Delegate works over the loopback address only, and only while the page's grant has Delegate on (the person's own switch). The page hands Claude a task: a title, what to do, and a copy of the documents chosen for it. Claude works on that copy on this computer, with no page and no workspace calls. The person can close the tab and come back later.
- **Where a task lives:** in `~/.sagebrush/tasks/<id>/`, a private folder (0700). Inside are the copy (`work/`), its history as a local git repository (`git/`, read it with `git --git-dir=<id>/git --work-tree=<id>/work log --all`), the task's events and its state. The task's grant, fixed when it starts, is recorded in its first commit. `~/.sagebrush/installation` holds this computer's id, which each task's grant is tied to. Delegate isn't available on Windows yet.
- **What Claude can do:** list, read and write the files of its copy (`workspace_list`, `workspace_read`, `workspace_write`, `workspace_write_notebook`), then propose it (`propose`). Nothing else: no shell, no files of this computer, no web, no settings, and no tool but these. Running code (`notebook_run`) is turned off in this version: it refuses and says why. See *Running code* below.
- **What the person does, in the page:** see the proposal as a difference from what Claude started with, then Merge it, Close the task, or Ask for changes. Claude then works again on the same copy, and its next turn gets the person's request exactly as they wrote it, with the paths whose versions in the person's request differ from the base. Stop ends Claude's turn; Resume carries on an interrupted task; Revoke closes it for good. The merge is done in the page: the agent only records what the page reports. Claude never merges, closes or answers for the person.
- **A turn that ends without a proposal** leaves the task interrupted, with the reason. So does stopping the agent, or turning Delegate off: a task that was working is interrupted, not closed, and only a Resume carries it on. Delegate is turned off when the paired page turns its switch off (a grant without Delegate after one with it, from the same pairing) or revokes the pairing. A page that goes away (a closed tab), or comes back and pairs again, changes nothing: the tasks go on. A new pairing starts with the switch off, so that page sees and controls the tasks again only once it turns the switch on.
- **Limits:**
  - at most 4 tasks working at once (more wait, at most 16), each turn at most 24 hours. A Start, Ask or Resume past that is refused before anything is recorded;
  - each task at most 512 MB on disk, of which the copy is at most 256 MB and 2,000 files, the event log at most 16 MB, and Claude's transcript at most 64 MB;
  - at most 64 tasks and 4 GB in all.
  - A start, an Ask or a Resume is refused while the disk has less free than the task's remaining room plus 64 MB.
  - While a turn runs, its transcript, the task's size and the free space are checked every half second. A turn past a limit is interrupted then, with the reason, whether or not Claude Code stops at once; nothing it sends after that is taken. Between two checks a turn can write a little past a limit: the 64 MB of free space kept is for that.
- **What is kept on disk:** the SDK keeps each task's transcript under `~/.claude/projects/`, in the folder named after the task's `sdk/` folder. Deleting it when the task is merged, closed or revoked is best effort, and is tried again whenever the agent loads a valid task that is already merged or closed. A deletion that fails can leave transcript bytes on disk, and they still count against the task's budget. Links are left alone on purpose: one in `~/.claude`, in its `projects` folder, in the task's transcript folder or inside it, or at the task's `sdk/` folder, is never followed, measured through or deleted, and the task can't start or take more work until it is gone (a `~/.claude` that is itself a link means Delegate can't be used). The task's own folder stays until you delete it.
- **What leaves your computer:** the task's conversation goes to Anthropic through the SDK, as with any Claude session. That includes the files of the copy that Claude reads. Nothing else goes anywhere.

**Running code** (in this version, off everywhere: `notebook_run` refuses with "Running code isn't available for Delegate on this computer: runs are turned off in this version"; a later, reviewed release turns it on). When it is on, it works like this:
- **Only for a task started with running code allowed**, on Linux or macOS (x64 or arm64). Anywhere else, or where anything below can't be had, the run is refused, saying why; editing and proposing go on. There is never a run with fewer limits instead.
- **What runs it:** a pinned Deno (2.9.0) and a pinned Sagebrush engine, each downloaded once from the npm registry, checked file by file against hashes in this package, kept in `~/.cache/sagebrush-agent/runner` (`~/Library/Caches/...` on macOS) and checked again before every run. Never a `deno` or `sagebrush` on your PATH.
- **What a run can touch:** it reads and writes only the task's copy and a fresh private scratch folder of its own (removed after the run), and reads the engine file. It has no network, can't start programs, has no native code, and sees none of this agent's environment: its environment is replaced whole (`HOME` is the copy; on macOS it also sets `__CF_USER_TEXT_ENCODING` from this account's uid, which macOS would otherwise add by itself during the run). The engine also confines itself to those two folders (`--confine`), refusing any link on the way. The zone data it needs (tzdata 2026.5, shipped in this package) is copied into the scratch folder for each run, checked against its pin, and counts against the task's storage.
- **Before and after a run** the copy is walked without following links: a link or a special file there and the run doesn't start, or its changes are undone. Claude's other tools wait while a run is going.
- **Before each run** the disk is asked again: with less free than the task's remaining room plus 64 MB, the run is refused before its scratch folder, zone data or process is created. While it runs, the copy and the run's scratch folder are watched with the transcript (every half second, at most 20,000 entries).
- **Stop, a limit or the time bound** (the cells' time, at most an hour, plus 30 seconds) kills the run's whole process group, waits for it to exit, and puts the copy back exactly as it was before the run.
- **If this agent itself stops** (a crash, a kill), the run stops with it: the run holds a pipe from the agent and ends when the pipe does. A record of the run (its process and start time, and the copy as it was before) is kept beside the task; at the next start, a run still there is ended (only if it is the same process, by its start time), and the copy is put back as before the run. If it can't be shown ended (its identity can't be read, or it may have started before it could be recorded), nothing is signalled and the task is left untouched, checked again at each start; deleting the task's folder discards it. If the run record can't be written once the process has started, the run is killed, undone and reported failed.

## With `sagebrush remote`

`sagebrush remote --serve-agents --agent-cmd "npx -y <the tarball's URL> --stdio"` runs it as the runner's child. The page reaches it through the runner, one message per line on stdin and stdout, so it listens on no port and prints no link.
- The runner's Stop stops the running turns. Stopping the runner stops the agent: it waits up to 1 second for turns to stop, then deletes this run's transcripts, as above.
- No message is over the runner's limit, about 4 MB. A bigger file write fails as an ordinary error that Claude sees.
- An Allow counts only when the page's answer carries the hash of exactly the action that was asked about.

**Shell and files on that computer.** When the page's grant says so (the person's switch "Allow shell and files on <computer>", on by default for their own computer), Claude runs there much as it does when they type `claude`:
- its own tools (Bash, Read, Edit, Write, …) and system prompt, plus the Sagebrush workspace tools;
- in the runner's working folder (where `sagebrush remote` was started), with the person's own settings: `~/.claude` and that folder's `.claude` and `CLAUDE.md` (their allow, ask and deny rules, their MCP servers). Files Claude writes there stay; only the empty folder of the tools-only mode is removed when the agent stops;
- the permission mode their settings choose there, as Claude Code resolves it; with none set, the default mode, as an interactive `claude` starts. A bypassPermissions setting isn't taken up either: it runs in the default mode, and the agent's log says so (one set only in the folder's own `.claude/settings.json` is dropped without a log line, as below). If the mode can't be read, the reply doesn't start. Anything Claude Code asks about comes to the page as a card, with the exact command, path or edit, and an Allow counts only for that action. Nothing is written to the settings.
- A mode set only in the folder's own `.claude/settings.json` that asks less than the default (acceptEdits, auto or bypassPermissions) isn't taken up: the default mode is used, where an interactive `claude` there might use that mode. An administrator's policyHelper isn't run when the mode is read.
- Moving or removing a file in the Sagebrush workspace is always asked, even when the person's own rules would allow it.
- With the switch off, it's the Sagebrush-tools-only mode above. Over the loopback address, it's always that mode, whatever the page asks.
- The mode is decided once per reply. Turning the switch changes the grant, so, as with any grant change, a running reply stops and waiting messages are dropped. The next reply runs in the new mode, as a new Claude session: Claude hasn't seen that chat's earlier turns.

**Codex.** `sagebrush remote --serve-agents --agent codex="npx -y <the tarball's URL> --codex --stdio"` offers Codex on that computer instead. It runs one pinned Codex release (0.159.2), not the `codex` on PATH: downloaded once from the npm registry (about 160 MB, the same bytes as OpenAI's own release), checked file by file against the hashes in this package, kept in `~/.cache/sagebrush-agent/codex` (`~/Library/Caches/...` on macOS) and checked again at every start. It runs as `codex app-server` with that computer's Codex login and settings (`~/.codex`), much as when they type `codex`:
- Codex needs shell and files: with the switch off, each message is refused with a line that says so, before Codex starts. `--codex` works only with `--stdio`.
- Each chat is its own Codex conversation, kept only while the agent runs (Codex saves no session files for it). It works in the runner's working folder, with Codex's own tools, the person's `~/.codex` settings, their MCP servers and the Sagebrush workspace tools. Files Codex writes there stay.
- What Codex asks before it acts, as their settings decide (a command, a file change, more access), comes to the page as a card showing exactly what Codex sent: the command and its folder, or every changed file with its diff. Allow accepts that one request only, never "for the session"; more access, once allowed, lasts until that reply ends. Anything else declines it, and a Stop cancels it. A file change Codex didn't announce first is declined. Codex reads files before it asks to change them, so declining a change doesn't undo what it has read.
- An approval_policy of `never` isn't taken up: the conversation starts with `on-request`, and the agent's log says so. Codex's questions to the person and its MCP servers' requests for input are declined; Codex is told to ask in the chat.
- Before its first conversation, that Codex is asked for its own protocol and checked against what this agent uses; if anything is missing, the reply says what, and nothing runs. If Codex isn't logged in, the reply says how to log in there.
- If Codex stops (or doesn't end a reply within 10 seconds of a Stop), the next message starts a new Codex conversation, which doesn't remember the earlier replies.
- What leaves the computer: the conversation, and what Codex reads, goes to the model provider in their Codex settings (OpenAI unless they changed it), as with any Codex session.

In both modes, at most 4 chats run at once (a fifth waits its turn) and at most 16 messages wait; a seventeenth is refused, and the page says so. `SAGEBRUSH_AGENT_FAKE=1`, set where you start it, runs a scripted fake model instead of Claude, for tests. With it, Delegate keeps its tasks only under the folder `SAGEBRUSH_TASKS_HOME` names, and is off without it.

Release: the tarball is published at an immutable, versioned URL with its SHA-256; a change means a new version and a new review.
